# Slice 34 — Pixel-art planet textures ("Pixel Space")

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The eight planets wear palette-locked pixel-art albedo maps (art-direction §10) — generated through a tool-gated AI pipeline, reviewed by Papa as one set, and wired into the scene with flat colour as the automatic fallback.

**Architecture:** Purely additive to `js/games/solar.js`: at build time each planet attempts to load `assets/solar/tex/<id>.png`; success ⇒ `map` on the existing Lambert material with nearest filtering; any failure ⇒ keep the flat data colour (the §4 look, forever canonical). The Sun, Saturn's ring, orbit rings and starfield are untouched. No data, sim or quiz changes.

**Tech Stack:** an image-generation route determined by the Task-1 gate (Magnific MCP if present and capable / Papa's generator / hand-tooling), Piskel or Aseprite for palette-locking, vendored Three.js, `scripts/check.mjs`.

**Design:** `design.md` D9 · **Binding:** `art-direction.md` §10 (format, palette, craft, features — all locked) · `tech-spec.md` §17

**Depends on:** slice 31 (the living scene). Independent of 32/33 — may run before, between or after them.

**DONE WHEN:**
- All eight maps exist, palette-locked, ≤ 40 KB each, precached; the scene renders them crisply on the tablet, offline; deleting any one map silently restores that planet's flat colour; the Sun and ring are untouched.
- `node scripts/check.mjs` passes; `assets/solar/tex/README.md` records tool, route and date per map.

---

## Constraints you must not violate

1. **Art-direction §10 is binding.** Format, ramp math, accent list, feature table — an agent that adds a colour, a feature or a soft pixel has shipped a bug.
2. **The gate decides the tool; the agent does not.** Task 1's outcome routes Tasks 2–3. No Magnific MCP is configured in this repo as of the design date — do not assume it exists.
3. **Never upscale a pixel map** (Magnific or otherwise). Crisp 128×64 or bust (§10.5).
4. **Offline-first:** every map joins `APP_SHELL` + `CACHE_NAME` bump in the same commit. Runtime never fetches a remote image.
5. **Fallback is sacred:** the loader must treat a missing/corrupt map as "use flat colour", never as an error state (tech-spec §17).

## Task 1: The tooling gate — GATE

- [ ] **Step 1: Enumerate what's actually available.** List the configured MCP servers and their tools (project `.mcp.json` + session tool list). Record the finding in `assets/solar/tex/README.md`.
- [ ] **Step 2: Route (exactly one):**
  - **Route A — a generation-capable MCP exists** (Magnific or other): Tasks 2–3 generate via MCP using the locked prompt sheet.
  - **Route B — only upscaling is available** (classic Magnific): pixel maps are generated by Papa's chosen generator or hand-tooled in Piskel/Aseprite; Magnific may *optionally* enhance the card NASA photos as a separate, skippable mini-task (§10.5). Maps never go near the upscaler.
  - **Route C — no image MCP at all:** Papa generates manually from the same locked prompt sheet; the agent does the palette-lock and wiring. **This route is the expected default.**
- [ ] **Step 3: Report the route to Papa before generating anything.** The gate exists so nobody burns an afternoon fighting the wrong tool.

## Task 2: The locked prompt sheet and generation

- [ ] **Step 1: Write `prompts.md`** — one prompt per planet, all sharing this locked style frame (fill the `<FEATURES>` slot from art-direction §10.4 verbatim):

```
pixel art planet surface, equirectangular map 2:1, flat albedo, no lighting,
no shadow, limited 6-colour palette, hard 1px edges, 50% checkerboard dither,
SNES 16-bit educational game style, base colour <BASE-HEX>, <FEATURES>,
plain black margins, seamless horizontal wrap
--no photorealistic, smooth gradients, blur, anti-aliasing, text, stars,
background, clouds of detail, outline
```

`<BASE-HEX>` is the body's locked `solar-data.js` colour, written out (e.g. "rust orange #C1440E"). Prompts are data: changing one means amending `prompts.md`, not improvising mid-generation.
- [ ] **Step 2: Generate candidates** — ≥ 2 per planet, downscale/crop to exactly 128×64 with **nearest-neighbour** (never bilinear).

## Task 3: Palette-lock + Papa's set review — GATE

- [ ] **Step 1: Palette-lock each candidate** in Piskel/Aseprite: posterize to the body's §10.2 ramp (+ permitted accents), fix stray colours pixel by pixel, verify ≤ 8 colours total, verify the wrap seam.
- [ ] **Step 2: Lay all eight side by side** (one contact sheet) and review **with Papa as a set** (§10.3 rule 6). Regenerate outliers — never "fix" coherence by lowering the bar for one planet. **Papa's sign-off is the gate; do not proceed on a solo judgment.**

## Task 4: Wire the textures

- [ ] **Step 1: Loader** per `tech-spec.md` §17: per planet, `TextureLoader.load("assets/solar/tex/<id>.png")`; on success set `NearestFilter` (mag+min), `generateMipmaps=false`, `colorSpace=SRGBColorSpace`, assign as material `map`; on error keep flat colour. Textures disposed in `stop()`.
- [ ] **Step 2: Precache + bump**: the 8 maps into `APP_SHELL`, `CACHE_NAME` bump.
- [ ] **Step 3: Optimise** each PNG (PNG-8 indexed, e.g. `pngquant`); confirm ≤ 40 KB each.
- [ ] **Step 4: Provenance**: fill `README.md` — per map: route, tool, prompt id, palette-lock date.

## Task 5: Tablet + commit

- [ ] **Step 1:** `node scripts/check.mjs` PASS.
- [ ] **Step 2: Offline tablet:** scene shows all eight textured planets crisp (no blur); focus-zoom in slice 32 still reads beautifully up close (pixels may be chunky at `size×4` — that is the style, not a bug); delete `mars.png` locally → Mars renders flat rust again, no console error; Sun + Saturn ring unchanged.
- [ ] **Step 3: Commit**

```bash
git add assets/solar/tex js/games/solar.js sw.js
git commit -m "feat(games): add palette-locked pixel-art planet textures"
```
